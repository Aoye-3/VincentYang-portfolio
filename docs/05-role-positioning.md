## 3. 板块增补优先级

### P0：把主案例的设计判断提到前面

每个精选案例入口增加“问题 / 我的贡献 / 可查看的成果”三项简要信息，进入案例后先用一屏说明，再展开现有板面。

案例中新增“关键设计决策”小节，每项使用“场景 → 备选方案 → 取舍 → 验证”的结构。优先从已有板面提取真实内容，补上当时为什么这样做、约束是什么。不要把事后建议写成当时已经完成的研究。

“数据驱动”要落到样本、任务、观察与设计变化：记录实际做过的访谈或测试方式、失败点、调整动作。若没有上线数据，说明原型验证阶段和局限。视频播放量用作创作传播结果，不用来证明产品体验改善。

### P0：增加一个“设计细节”入口

建议放在精选作品之后，采用大图局部放大、改版前后切换或状态演示；点击后进入对应案例锚点。延续现有黑色视觉，突出真实界面与少量说明。

三个可选主题：

- **视觉与排版**：信息层级、字重、间距、对齐、密度为什么这样设定。
- **组件与状态**：输入、选择、加载、空状态、错误状态的规则；以实际已有设计为准。
- **动效与实现**：反馈发生的时机、节奏和缓动；设计稿与实现的细节对照。

现有 Token / 组件板面可直接成为这一入口的内容起点。避免只展示整张 Figma 画布；用一两个可读的局部说明决策和复用关系。

### P1：补充“从原型到真实产品”

在 PMAgent 案例中提供 30–60 秒任务演示，例如现有素材组织、生成或分镜工作流。展示问题、主要操作与结果，并明确本人负责范围；链接只使用真实可访问的 Demo 或仓库。

AI 交互部分可补充生成等待、失败重试、取消、撤销、结果比较等实际已实现或已设计的状态。未实现状态应明确标为后续方案。说明模型限制如何影响反馈、用户控制权及功能边界。

关于“开源模型二次开发”，在案例里准确区分模型接入、推理流程改造、应用封装与训练 / 微调；只写实际完成的工作。技术名词服务于设计问题与结果。

### P1：充实现有兴趣折叠区

保持点击展开。增加少量手绘 / 平面作品与对应过程图；AIGC 视频提供成片、分镜、剪辑 / 声音等本人贡献。播放量标注单条数据、平台和统计日期；正文可使用用户提供的“多条作品在抖音播放量破万”。

这些材料放在兴趣区提供长期创作证据，主背景继续使用 UX 与证书。可增加开源维护记录入口，指向真实 issue 处理、版本更新或贡献说明；不编造社区规模与下载数。

### P1：补充投递入口和英文材料

页尾建议提供公开用途的简历、联系渠道和英文案例摘要。联系信息使用本人指定可公开的内容。英文摘要优先覆盖问题、角色、关键决策与结果；不要仅翻译按钮。

## 4. “关于我”推荐文案

> 我有长期的平面设计与手绘积累，也参与用户研究、交互设计和组件库搭建。设计时，我关注信息层级、视觉细节，以及一个想法能否在真实任务中顺畅使用。
>
> 在 Agent 与画布工具实践中，我结合对 LLM 基本机制和能力边界的理解，用 Vibe Coding 搭建可交互原型与 MVP，验证工作流，并继续打磨实现细节。
>
> 工作之外，我持续进行 AIGC 视频创作，多条作品在抖音播放量破万，也参与开源社区维护。创作、使用工具和持续迭代的过程，为我的设计提供具体的问题与灵感。

技能叙述的落点建议：

- “审美好” → 展示一次具体的视觉取舍和最终效果。
- “熟悉 Vibe Coding” → 展示从原型到可运行验证的过程。
- “理解 Agent” → 展示如何设计可理解、可控的操作与反馈。
- “数据驱动” → 展示观察、数据与设计修改之间的关系。
- “有开源经验” → 展示维护和协作记录。

## 5. 需要补齐的真实材料

优先收集：两组设计前后对比、一套组件状态、一次测试记录、一段产品任务演示、两条视频公开链接及统计日期、一份英文说明或协作记录。拿到素材后，再实现对应模块和可访问入口。

时间信息需在后续整体验证时统一：当前经历区显示 Goldsmiths `2025 — 2026`，本次用户更新的预计毕业日期为 `2027 年 1 月`；应根据实际入学、结课与授予学位时间，区分标注，避免将其中一个时间直接猜成另一个。
